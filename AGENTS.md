# AGENTS.md

Ambar keeps a moment (a photo, a short clip or a link) and leaves it visible afterwards, on any device, sharing only what the user chooses.

## Rules

1. **English only.** The repository and the product are in English: code, identifiers, comments, docs, commit messages, UI copy and metadata (`lang="en"`). Do not write Spanish (or any other language) unless the project owner explicitly asks for it for a specific page or text. Never translate on your own initiative.
2. **Bun only** for JavaScript. npm, pnpm, yarn and similar are forbidden. Install with `bun add` / `bun add -d`, run with `bun run` and `bunx --bun`. The only lockfile is `bun.lock`. After adding or removing a dependency, restart any running dev server: Vite serves stale optimized deps (504 "Outdated Optimize Dep") and islands silently stop hydrating. `apps/api` is Go: its dependencies are Go modules (`go get`, `go.mod`), and its tasks still run through Bun scripts (`bun run dev:api`, `test:api`, `--filter @ambar/api …`).
3. **Everything in Tailwind.** Styles are written with Tailwind utilities. `packages/ui/src/styles/globals.css` is the only global CSS and is edited only when strictly necessary (`@theme` tokens, shadcn variables, fonts).
4. **No nested packages.** Every package lives directly under `apps/*` or `packages/*`. No `packages/ui/packages/...`.

## Structure

- `apps/web`: public site. Astro + React islands + Motion.
- `apps/app`: web app. Vite + React + React Router.
- `apps/api`: backend. Go (latest) + chi + PostgreSQL (pgx), one static binary for the VPS. See **API** below.
- `packages/ui` (`@ambar/ui`): shared components and screens (React).
- `packages/core` (`@ambar/core`): UI-free logic (session, upload URL, domain types). No React, no DOM.

Upcoming apps: `apps/extension`, `apps/desktop`, `apps/mobile`. Reusable code goes in `packages/ui` or `packages/core` and is never duplicated across apps.

## Component philosophy

Shared components will run in very different places: the web, a desktop app, a browser extension and mobile. They must be well built, secure, frictionless and, above all, **portable**. That never means more code: if a component already meets these points, leave it as it is.

**Portability**
- `@ambar/core` is plain TypeScript: no DOM, no React, no platform APIs. Contracts, validation and domain rules that must run everywhere live here.
- `@ambar/ui` is React DOM and only uses standard web APIs (storage, IndexedDB, canvas, clipboard), which exist in browsers, desktop webviews and extension pages. Guard each one: it can be missing or blocked. A native mobile app reuses `@ambar/core`; `@ambar/ui` reaches mobile only through a webview.
- Platform decisions come in as props, never from inside a shared component: navigation (`onDone`), where tokens come from (`verifyToken`), which backend (`apiUrl`). Reading the URL, routing and `window.location` belong to the app or to an app-specific wrapper (e.g. the landing's `FirstMomentDialog` around the shared `KeepFlow`).
- Props that cross an Astro island boundary must be serializable: strings like `apiUrl`, never client objects or callbacks.

**Security**
- Client-side checks (file type and size, email shape, code length) exist for UX; the server is the authority and validates again.
- Real auth never keeps tokens in JS-readable storage: httpOnly cookies on the web, the OS keychain on desktop and mobile, `chrome.storage.session` in the extension. `localStorage` sessions exist only in the mock clients.
- One-time tokens leave the URL as soon as they are read (`history.replaceState` or a router replace).
- No `dangerouslySetInnerHTML`. External links open with `rel="noreferrer"`. User files are shown through `createMomentPreview` (decoded, resized, revoked), never as-is.

**Low friction**
- Native behavior before re-implementing it: real `<button>`, inputs with the right `type`, `inputMode` and `autocomplete` (`email`, `one-time-code`), so paste and autofill just work. One native input beats several synthetic ones (see `CodeInput`).
- Accessible primitives come from Base UI; keyboard, focus and ARIA must keep working after styling.
- Never lose the user's work or focus: keep focus on an error so they can retry, keep the dropped moment until it is uploaded, auto-submit when an input is complete, prefill what we already know.
- Check every component with the keyboard, axe (0 violations) and reduced motion.

**Simplicity**
- Add a dependency only when it removes more than it adds: complex or security-sensitive problems get a well-maintained library (e.g. react-dropzone); small, well-understood pieces (~100 lines) stay our own code (e.g. `CodeInput` instead of `input-otp`).
- No options, layers or abstractions "just in case".

## Conventions

- **Components:** shadcn on Base UI (`base-maia`) for primitives like card, input and label. Add them with `bunx --bun shadcn@latest add <component> -c apps/app`; they land in `packages/ui`. Never `shadcn add button`: it would overwrite the tactile Button.
- **Buttons:** the tactile `Button` from `@ambar/ui/components/button` (tones `ink` main action, `leaf` confirm or save, `sky` share, `cloud` neutral, `danger` destroy; sizes `sm`, `md`, `lg`, `icon-sm`, `icon`, `icon-lg`; `loading`). Use `buttonVariants()` to style an `<a>`. Controls with their own behavior: `CopyButton`, `SaveToggle`, `SegmentedControl`, `Switch`, `HoldButton`. All share `@ambar/ui/lib/tactile`.
- **Focus:** Tailwind v4 `outline-none` and `outline-hidden` set the outline style to none, so `focus-visible:outline-2` alone draws nothing. Always pair it with `focus-visible:outline-solid`. Do not include `outline-color` in transitions.
- **Icons:** Phosphor (`@phosphor-icons/react`). Do not use lucide.
- **Typography:** Figtree for body text (`font-sans`), Averia Sans Libre 700 for headings (`font-heading`, applied to h1–h6).
- **Color:** primaries `ink` (black: text, primary button) and `cloud` (white: background, cards). Secondaries from the reference frames: `sky` (#93bbcb; fills and tints with ink text, never text), `sky-deep` (#3f6f80, the same hue at 5.5:1 on cloud: blue text and links, e.g. a kept link's URL; never fills) and `leaf` (#537234; text accents, links, focus, fills with cloud text). Grays come from the shadcn semantic tokens (cloud mixed toward ink). Never Tailwind default palettes and no new brand colors without the owner. Destructive red is functional only. Token names are English. Palette lives at `/dev/colors`.
- **Resin:** `resin` (#e09a2f) is the one exception to the palette and exists only for the amber specimen on the pricing section (`apps/web/src/components/amber-specimen.astro`). Never use it for text or UI.
- **Brand name:** always `Ambar`, plain ASCII, in every text: copy, titles, metadata, alt and screen-reader text, code and docs. The accent exists only as a drawing: the leaf over the A in the wordmark (`apps/web/src/components/wordmark.astro`), never as the character `Á`.
- **Product terms:** OCR is called **readings** ("Ambar reads the words in your photos so you can find them later"). Plans and limits live only in `@ambar/core` (`plans.ts`); where Ambar runs (web, extension, mobile, desktop, status and download URL) only in `@ambar/core` (`platforms.ts`), shared by the landing's Platforms section and the app's "Get Ambar" menu.
- **Animation:** CSS first (`tw-animate-css`, Tailwind transitions, always with `motion-reduce:`). Motion (`motion/react`) only when CSS cannot do it; on the landing it costs ~100 KB of JS per island.
- **Signature motion:** two named effects. **Develop** (darkroom: from overexposed, flat and soft to sharp) is the onboarding of every "Start keeping" (`FirstMomentDialog`, always with `backdropSrc={onboardingBackdrop}` from `apps/web/src/lib/onboarding.ts`). **Shutter** (`@ambar/ui/components/shutter`, six ink · leaf · sky slats, pure CSS) is for other sections: `<Shutter closed={…} />` in a relative container. Both are replayable at `/dev/motion`. **Iris** (`@ambar/ui/components/iris`) is the landing → app handoff: the keep flow shows the mark centered at the top of the dialog from the email step; after "Kept." the iris closes onto that logo (`origin`), the mark glides to the center and the landing navigates with `?entry=iris`; the app's `index.html` paints that closed frame before any JS (inline script + critical CSS, the one place outside Tailwind; the mark is inlined as `<svg>` by a Vite plugin from `@ambar/ui/lib/mark-svg`, never an `<img>`) and `AppLayout` opens it once the first route renders, then strips the flag. Reduced motion skips it. **Iris onto a provider** (`useProviderHandoff`, `@ambar/ui/components/provider-handoff`): choosing Google or GitHub closes the iris onto that button's logo (`Iris` `mark`), then the Ambar mark develops beside it with three pulsing dots and "Connecting to Google…" while the browser leaves; coming back, the app's cover opens it as on every arrival. Replayable at `/dev/motion`.
- **Frame:** every surface uses the landing's frame from `@ambar/ui/lib/layout` (`PAGE_FRAME`, `PILL_HEADER*`, `PILL_LINK`), so the app reads as the same place. The app's content uses `APP_FRAME` instead (up to `max-w-app`, 100 rem) with the fluid `gutter` spacing (`px-gutter`, `gap-gutter`: 16 px on a phone growing to 48 px), so resizing never jumps. Brand assets (the mark and its variants) live in `packages/ui/src/assets/logo`; its geometry in `@ambar/ui/lib/mark-paths`, drawn by the Astro `Mark` and the React `Mark` (`@ambar/ui/components/mark`). Draw the logo as inline SVG, never as an `<img>` that can fail to load.
- **Loading:** anything that renders after first paint goes through `SkeletonSwap` (`@ambar/ui/components/skeleton-swap`): skeleton and content share one box (reserve its size with a `min-h-*` while loading), no skeleton under 120 ms, at least 380 ms once shown, `aria-busy` and a "… loaded" status. Shapes from `SkeletonBlock` / `SkeletonLines`. Uploads show `ProgressBar` (`@ambar/ui/components/progress-bar`: native `<progress>` for assistive tech, leaf fill in the tactile well, indeterminate until the first progress). Never a spinner where the size of what is coming is known. Both follow interior.dev's Skeleton Swap and Progress Bar; specimens at `/dev/feedback`.
- **Lazy UI:** preload heavy chunks on intent (pointerenter, focus, touchstart) and, once loaded, render the module directly instead of through `lazy`/Suspense, which holds the fallback ~300 ms even when the code is ready. Animate media only after it has loaded. Encode a given photo once and share the URL (e.g. `skyPhoto` in `apps/web/src/lib/onboarding.ts`), never two variants of the same picture on one page. Never display user photos at full resolution: use `createMomentPreview` (`@ambar/ui/lib/preview`).
- **Sign in and sign up (`AuthFlow`, `@ambar/ui/components/auth-flow`):** one flow for every surface: the landing dialog (lazy `auth-dialog-content.tsx`) and the app's `/login`. Two modes, switched by a link under the form ("New to Ambar? Create an account" / "Already have an account? Sign in"): the **Shutter** closes over the whole surface (`FlowSplit` `switching`), the panes trade places behind it (`mediaSide`: sign in left, sign up right) and the words change, then it opens; reduced motion swaps instantly. Sign in: email → code. Sign up: "It all starts with a moment." + dropzone (optional, "Skip for now"), then email → code. Both share `KeepFlow` (`mode` prop) and one backend flow: asking for a code never reveals whether an account exists; verifying returns `created`, and the ending says "Welcome to Ambar" or "Welcome back". The moment stays in view as a compact `MomentCard` row. `createClients(apiUrl)` returns the HTTP client when an API URL is set, else the mock (code `123456`, same rules: tries left, created).
- **Continue with Google / GitHub:** `ProviderButtons` under the email form ("or" divider), cloud `lg` tactile keys with the providers' own logos (`ProviderLogo`; Google's four colors are required by its branding and are not Ambar colors). Only providers `AuthClient.providers()` lists are shown. The platform reads what the browser comes back with (`readAuthReturn`: `?verify=`, `?oauth=`, `?error=`), passes it as `authReturn` and strips `AUTH_RETURN_PARAMS`; the flow finishes signing in (keeping a pending moment) or shows the error on the email step. Where providers return (`providerReturnTo`): the app `/login?entry=iris` (the cover stays shut until it opens on the moments); the landing only when a moment is waiting on its origin. The mock signs in as `you@<provider>.example` and comes straight back.
- **Settings · Sign-in methods:** `SignInMethods` (`@ambar/ui/screens/settings/sign-in-methods`), a card like the others: one row per method, always all of them (`PROVIDERS`; one the server has not configured shows "Not available" and a disabled Connect) (logo on a muted disc, "Sign in with …", the connected email, a cloud `sm` Connect / Disconnect). Connect plays the provider handoff with `intent: "link"` and returns to `/settings?entry=iris` (`?oauth=linked` or `?error=`, toasts in the route); Disconnect is one tap, no confirm, focus stays on the row's button. Connected rows show a leaf check and "Connected"; if the connected accounts can't be read, the rows stay disabled and the card says so (never "Connect" for an account that may be connected). "Sign in with email and password" is a disabled "Enable" placeholder until passwords exist: never wire it up without the owner.
- **Email links return where the flow started:** the client sends `returnTo` (landing `/`, app `/login`; the API keeps it only on an allowed origin), because the pending moment lives in that origin's IndexedDB. A link token works once: `KeepFlow` verifies each token once per mount, so React StrictMode's double effects in dev never send it twice.
- **Limits are shown, not just enforced:** `invalid-code` carries `attemptsLeft` ("2 tries left"); `too-many-attempts` disables the code input and makes "Get a new code" the focused primary action (no cooldown for a dead code); `rate-limited` carries `retryAfterMs` and the email/code steps count down ("Try again in 42:10"). Countdown helpers: `@ambar/ui/lib/countdown`.
- **Sign in never leaves the page:** the landing's buttons open the dialog in the matching mode (Start keeping → sign up, Sign in → sign in). Both surfaces show `FlowLogo` on top and end the same way: the iris closes onto it and opens on the moments (`?entry=iris`). The dialog is `FRAME_WIDTH` wide (`@ambar/ui/lib/layout`), so its sides line up with the page content.
- **Annotations:** `Annotation` (`@ambar/ui/components/annotation`) draws a hand-made underline or strike in leaf, like a pen stroke, when `drawn` turns true (and on first paint). Use it sparingly, only on words that carry the point (e.g. pricing: "forever", the struck full-year price, "save 20%"). Values that change in place (a price) swap with a develop-style CSS transition, never a hard cut; screen readers get the new value through an `aria-live` line while the animated copy is `aria-hidden`.
- **Menus:** Base UI `Menu` dressed by `@ambar/ui/components/menu` (`MenuRoot`, `MenuTrigger`, `MenuContent`, `MenuItem`, `MenuLinkItem`, `MenuGroupLabel`, `MenuSeparator`): the header pill's glass surface, keyboard and focus from Base UI. Pass `container` (the landmark the trigger lives in, e.g. the header) so the open menu stays inside a landmark. Ready-made: `UserMenu` (account, Settings, Sign out) and `GetAmbarMenu` (other platforms; disabled with their status until they have a `downloadUrl`).
- **Session in the app:** `useSession(apiUrl)` (`@ambar/ui/lib/session`) in `AppLayout`, read once on mount (latest read wins) and re-read only when it changes elsewhere: `/login` calls `refresh()` when the flow ends, in parallel with the iris. Never re-fetch it per route. Routes read it with `useAppSession()` from `apps/app/src/session.ts` (route files export only components). Routes not needed on first paint (`/login`, `/settings`) are `lazy`. Signed in, the header shows `UserMenu` · sections · `GetAmbarMenu`. Private routes live under the pathless `RequireSession` route in `router.tsx` (everything but `/login`; a new route goes there unless it is meant for anyone): nothing renders until the session is known, signed out the app replaces itself with the public site (`VITE_SITE_URL`), and so does signing out. The viewer and the search mount only with a session. This gate is UX; the API's `authenticated` group is what protects data. A page restored from the back/forward cache re-reads the session, so Back after signing out never shows the library. If the session can't be read (network, server), the app says so ("We can't reach Ambar", Try again) instead of guessing.
- **Lint:** oxlint with the anti-slop rules vendored in `tools/oxlint/anti-slop`, plus the `react` (hooks) and `jsx-a11y` plugins. For "run once, read the latest values" effects use `useEffectEvent`, never an `exhaustive-deps` disable. Every remaining `oxlint-disable` carries its reason after `--`.
- **Motion tokens:** easing lives in one place. Motion (JS) uses `EASE` from `@ambar/ui/lib/motion` (`develop`, `outSoft`, `iris`) and the develop filters; CSS uses the theme tokens `ease-out-soft`, `ease-settle`, `ease-tactile`, `ease-spring`, `ease-shutter` (globals.css). Never inline an easing array or `cubic-bezier(...)`.
- **Shared helpers:** `wait` (`lib/wait`), guarded `localStorage` (`lib/storage`: `readItem/writeItem/removeItem`), the iris handoff contract (`IRIS_ENTRY`, `isIrisEntry`, `withIrisEntry`) and `useIrisExit` (logo ref + close + closing iris) in `@ambar/ui/components/iris`. Reuse them instead of re-writing the pattern.

## Library (the app)

- **What it holds:** moments of four kinds (`photo`, `clip`, `link`, `file` = PDF), each with `title`, `source`, `topics`, `readings` (OCR) and `collectionIds` (`@ambar/core` `moment.ts`). PDFs: the server renders the first page and reads the text when kept; clients never ship a PDF renderer and open PDFs in the platform's viewer.
- **Structure:** sections live in the pill header: **Moments** `/` (the timeline), **Collections** `/collections` (`/collections/:id`), **Canvas** `/canvas` (full-bleed board, route handle `FULL_BLEED`). Secondary places sit in the avatar menu: **Trash** `/trash`, Settings. The moment viewer is global (`?m=<id>` on any section, `MomentViewerHost`).
- **Moments views:** 2×2, 3×3, 4×4 (grid density, capped by the container) and **List**, remembered per device (`useMomentsView`, `ambar.moments-view`). List (`MomentList`): a color-coded text badge for type at the left, title, keeper avatar dock near the middle-right and saved date/time at the right, newest first, with no media thumbnails or date headers (an ARIA listbox; selection follows focus; arrows and Home/End follow the rendered order; Enter opens the viewer). Reveal 50 rows at a time, automatically near the end or through Load more; this batches rendering only, preserving the complete library for search and Canvas. From 48 rem of container width, use 45% for the independently scrolling list and 55% for a fixed preview panel, separated by `gap-gutter`. Center the uncropped media in a 16:9 frame, up to 50 rem wide and 45dvh tall. Below: title, source, direct Edit title / Canvas / Trash buttons, then More details with URL (or Open original) and Saved, followed by secondary copy/download/open actions. Dates use English month names, a 24-hour clock and the device's timezone. The panel may scroll in short windows. Narrow: the list alone, dates below titles, a tap opens the viewer.
- **Kind filter:** chips in the Moments header (`SegmentedControl`, controlled): All plus only the kinds that exist, each with its count (`countByKind` / `filterByKind` in `@ambar/core`); hidden with a single kind. Applies to every view, is never remembered (reload = All) and falls back to All when the chosen kind empties; the count badge reads "7 of 21" and a status line announces it. Cards move with View Transitions (`moveInPlace`, `@ambar/ui/lib/view-transition`: names only during the change, items carry `data-moment-id`), instant with reduced motion or without the API. Never Motion for this.
- **Embedded pages:** the server decides at keep time whether a link can be shown inside Ambar (`LinkMoment.embed`: "page" if the site allows framing, "player" for official oEmbed players, absent otherwise); the client never guesses and never shows a broken frame (no embed = capture + "can't be shown inside Ambar" + Open original). The live page loads only on "Browse page" / "Play", one at a time (changing selection leaves it), over the capture until it paints, in a sandboxed iframe (`allow-scripts allow-same-origin allow-forms allow-popups`, no top navigation, `referrerPolicy="no-referrer"`).
- **Search vs the agent:** search is the ⌘K / `/` palette (`SearchPalette`): instant, local, free (moments via `matchesFilter`, collections, places). It **never** calls the agent. Only the explicit last row "Ask Ambar: …" (or ⌘Enter) does, through `useAsk`; its answer shows in the palette. Keep that line: every agent call costs tokens. The ranking, time phrases and grouping are pure functions in `@ambar/core` `library.ts` (tested with `bun test`), shared by every client and the agent.
- **The answer:** best match large, why it matched, up to four others, and the best match **already copied** (image as PNG, or the link). If the browser blocks the copy, "Copy" becomes the primary action. Copy, Download and Open are always one tap away (cards, answer, viewer).
- **Trash:** deleting is reversible: it moves the moment to the Trash (`deletedAt`, `TRASH_DAYS` = 30, `trashDaysLeft`) with an Undo toast, no confirmation. Only irreversible actions confirm (`ConfirmDialog`: Empty Trash). The server erases expired items; the mock does it when listing.
- **Chrome that steps aside:** the header uses `useAutoHide` (`@ambar/ui/lib/auto-hide`): hides on scroll down, returns on scroll up, pointer at the top edge, any key or focus inside (never hides with focus inside). Full-bleed screens (Canvas) also hide it after 2.5 s idle; moving around the content doesn't bring it back.
- **Keeping:** paste or drop anywhere keeps at once, no form. The composer (`KeepComposer`, `@ambar/ui/screens/library/keep-composer`) is a "+ Keep" pill at the bottom right that stretches left into a slim bar (link, Upload, Keep ▾, ✕): paste + Enter keeps in one step. Extras appear only when asked for: once something is in, "+ Tags" (chips, suggestions from `suggestTags` in `@ambar/core`, stored with the topics), "+ Collection" and "+ Note" each open just their field above the bar. ▾ on Keep is "Keep on" (devices; Keep shows their icons): a prototype on `MOCK_DEVICES` (`@ambar/core` `devices.ts`, availability from `PLATFORMS`), nothing syncs; never wire it up without the owner. Escape or ✕ fold it back keeping the draft. Ambar still names it and the toast offers the matching collection when none was chosen.
- **Portability:** screens live in `@ambar/ui/screens/library` and take navigation as callbacks (no router inside); layouts use container queries (`@container`, `@2xl:`), never viewport breakpoints, so the same screens fit an extension popup, a desktop window, a phone webview and the web. Viewport-level overlays (the viewer dialog) may use viewport breakpoints. What differs per platform (clipboard, save, open, share) is `PlatformActions` (`@ambar/ui/lib/platform-actions`), provided by each app; the web one is the default. Data comes through `LibraryClient` (`@ambar/core`); `createMockLibrary` stands in until the API serves it, and the answer panel shows "Simulated" meanwhile. Never `window.prompt`/`alert` (desktop shells and extension popups don't support them): use `PromptDialog` and toasts.
- **Toasts:** `ToastProvider` + `Toaster` (`@ambar/ui/components/toaster`, Base UI Toast), one per app.

## Environment

- **One `.env.example` per deployable app** (`apps/api`, `apps/web`, `apps/app`), committed and listing every variable with a one-line comment, as direct as possible. Local values go in `.env.local` next to it (gitignored by `.env.*`). No root `.env`: each app deploys on its own.
- **Secrets live only in `apps/api`.** Frontend variables are bundled into public JavaScript (`PUBLIC_` for Astro, `VITE_` for Vite), so the frontends only hold URLs. Nothing is duplicated across apps.
- **Validated in one place, failing at start:** the API in `main.go` (production refuses missing secrets), the landing with the `astro:env` schema in `astro.config.ts` (read via `astro:env/client`), the app with `src/env.ts` (Valibot), parsed by `vite.config.ts` and read via `src/api-url.ts`. A bad value stops dev/build, never the user's browser.
- The API loads `.env.local` itself (godotenv, never overriding real variables) so `bun run dev:api`, `go run .` and the IDE behave the same; on the VPS the service environment is the only source. When a team or several environments appear, secrets move to a manager (Doppler, Infisical, 1Password), not to more files.

## API

- **Simple first.** `apps/api` is a flat `package main` (`main.go` wiring and shutdown, `routes.go` every route, `auth_handlers.go`, `middleware.go`) plus packages only where there is code to separate: `auth` (sign-in rules + SQL), `mail` (Resend, console in dev), `migrations` (embedded SQL, goose). Follows go.dev/doc/modules/layout. Add a package only when there is code to separate, named after what it does (`auth`, `store`), never `utils`, `common` or `httpapi`. No folders "for later".
- **Libraries over code:** chi and its middleware (`RequestID`, `Recoverer`), httprate, pgx, goose, resend-go (v4), godotenv.
- **Dependencies fail; plan for it.** Every outbound call has a time budget (Resend: 10 s for a send, retries included). Retries only for idempotent requests and transient failures (network, 5xx, 429 with a short `Retry-After`), with backoff and jitter (`mail/retry.go`); 4xx are never retried. Provider errors are mapped to our own (`mail.ErrRateLimited`, `ErrRejected`, `ErrUnavailable`) and never carry the provider's text, which can echo user data. Log the provider's id on success (`resend_id`) to trace a message end to end. Write our own only when the library is wrong for us (e.g. `realIP`: chi's `RealIP` trusts client-controlled headers).
- **Config:** environment variables read only in `main.go`, all listed in `apps/api/.env.example`. `ADDR`, `DATABASE_URL`, `APP_URL` and `ALLOWED_ORIGINS` are required: no address, URL or credential is written in the code (tests read `DATABASE_URL` from `.env.local` too).
- **Contract first:** `apps/api/openapi.yaml` (OpenAPI 3.1) describes every endpoint before it is written; `bun run lint:openapi` lints it and the Go tests validate every response against it (`contract_test.go`). Design rules: `docs/explanation/api-design.md`; new endpoint checklist: `docs/how-to/add-an-endpoint.md`.
- **Errors:** RFC 9457 problem documents (`application/problem+json`) via `writeProblem` / `writeProblemWith`: `type`, `title`, `status`, `detail` (end-user copy), `code` (stable, kebab-case, what clients switch on), `requestId`, plus extensions (`attemptsLeft`, `retryAfterMs`). Catalog: `docs/reference/errors.md`. Never an ad hoc error shape, never internal text in `detail`.
- **Logs:** `log/slog`, one line per request with OpenTelemetry attribute names (`request_id`, `http.request.method`, `http.route` = route **pattern**, `http.response.status_code`, `duration_ms`, `client.address`); domain events carry `event` (`auth.signed_in`, …). Every response returns `X-Request-Id`. Catalog: `docs/reference/logs.md`. Never log raw paths, queries, tokens, codes, emails or the database URL.
- **Client IP:** `TRUST_PROXY=true` only when the API is reachable solely through our reverse proxy, which must set `X-Real-IP`. The rate limit (120/min per IP, IPv6 per /64) depends on it.
- **Migrations:** applied at start under a Postgres advisory lock (goose session locker), so parallel test packages or two instances never race.
- **Health:** `GET /healthz` pings Postgres (200 / 503). The API starts even if the database is down.
- **Auth (stateful, passwordless):** `POST /v1/auth/email` {email, returnTo?} → 202 (same answer whether the account exists), `POST /v1/auth/email/verify` {email, code} | {token}, `GET` / `DELETE /v1/auth/session`. One challenge per email carries a 6-digit code and a link token; using either consumes both. Rules live in `auth/auth.go`: 10-min expiry, 30 s resend cooldown (asking again sooner sends nothing), 5 emails/hour per address, 5 wrong codes burn it, only the newest email works, provider failure keeps nothing. Sign up = first verified sign-in. Consuming the challenge, creating the user and opening the session are one transaction: if any step fails, the code or link still works. Signing in always lands on the app's home (`/`). `main.go` runs `auth.Service.Cleanup` hourly: challenges older than a day and sessions expired or revoked a day ago are deleted.
- **Sessions:** opaque 256-bit tokens, only their SHA-256 in `sessions`; one row per device, 30 days sliding (renewed at most daily), never past 90 days from sign-in, revocable. Web: `__Host-session` cookie in production (`session` on plain-http dev): HttpOnly, SameSite=Lax, Secure, host-only on the API's host, never readable by scripts. Landing, app and API are same-site, so no `Domain` is needed. Native clients send `client: "native"` on verify, keep the token in the OS keychain and send `Authorization: Bearer`.
- **Never consume a link with GET:** mail scanners prefetch links. The email links to the app (`APP_URL/login?verify=…`), which POSTs the token and removes it from the URL; landing and app send `Referrer-Policy: no-referrer` (meta tag), so the URL never leaks.
- **Secrets:** codes are stored as HMAC-SHA256 with `AUTH_SECRET` (salted per challenge), tokens as SHA-256; nothing sensitive is logged (emails, codes and tokens only appear in the dev console mailer).
- **Domains:** landing `ambar.page` (Cloudflare, static `apps/web`), app `app.ambar.page`, API `api.ambar.page` (VPS, behind the reverse proxy), email from `hi@ambar.page`.
- **IDs:** internal tables use time-ordered UUIDv7 (`DEFAULT uuidv7()`, Postgres 18): index-friendly inserts, and `uuid_extract_timestamp(id)` tells when a row was created. Ids that reach clients and would reveal something about a person (`users`: signup date) stay random UUIDv4 (`gen_random_uuid()`).
- **Private by default:** every route that touches an account's data sits in the `authenticated` group in `routes.go` (middleware: 401 before the handler, session via `sessionFrom`). `TestPrivateByDefault` walks the router and fails for any route outside it that isn't on its public list. The app's route guard is UX; the API is the authority.
- **CSRF:** SameSite=Lax + JSON-only bodies + `Origin` checked against `ALLOWED_ORIGINS` on every state-changing request.
- **Clients:** `createHttpAuth` (`@ambar/ui/lib/http-auth`) implements `AuthClient` over the API when `VITE_API_URL` / `PUBLIC_API_URL` are set; responses are decoded with the Valibot schemas in `@ambar/core` (`api.ts`).
- **Google and GitHub sign-in:** `apps/api/oauth` (`golang.org/x/oauth2`, authorization code + PKCE, run by the API so the secret stays there). Browsers navigate to `GET /v1/auth/oauth/{provider}?returnTo=…`; the provider returns to `API_URL/v1/auth/oauth/{provider}/callback`, which signs in onto the same users and sessions (`user_identities`, joined by provider-verified email) and redirects back to `returnTo` with `?oauth=created|signed-in` or `?error=oauth-…`. `GET /v1/auth/providers` lists the configured ones. A provider is on only when its client id and secret are set. Decision 0005; setup in `docs/how-to/set-up-provider-sign-in.md`.
- **Checks:** `bun run --filter @ambar/api typecheck` (gofmt, `go vet`, staticcheck) and `bun run test:api` (`go test -race`). Dev database: `bun run --filter @ambar/api db:up` (Docker through Colima: `colima start`). Auth tests run against it; `go test -short` skips them.

## Design system

- The gallery lives in `apps/web/src/dev` and is served at `/dev` only during `bun run dev:web`; it is never in the build. Add a section in `src/dev/sections.ts` plus `src/dev/pages/<slug>.astro`.
- Every specimen is shown on `cloud` and on `ink` (future dark mode).
- External components (e.g. opensourceui.in) enter as lab candidates in `apps/web/src/dev/lab`, then move to `packages/ui` once approved and the lab copy is deleted.
- When adapting one: keep the native element and its keyboard/ARIA behavior, swap lucide for Phosphor, replace default palettes and gray/black values with brand or semantic tokens, drop `forwardRef` and `"use client"`, import `cn` from `@ambar/ui/lib/utils`, and credit the source in a header comment.
- One button system: the tactile `Button`. New looks become tones of it; only components with their own behavior are separate.
