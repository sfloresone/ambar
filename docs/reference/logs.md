# Logs

The API logs with `log/slog` to stdout: text in development, JSON with `LOG_FORMAT=json` in production. Field names follow the [OpenTelemetry semantic conventions](https://opentelemetry.io/docs/specs/semconv/) (decision [0003](../decisions/0003-log-fields-follow-otel.md)) so log backends understand them without mapping.

## Request line

`requestLogger` (`apps/api/middleware.go`) writes one line per request with `msg="request"`. Level is `INFO` for 2xx/3xx, `WARN` for 4xx and `ERROR` for 5xx.

| Field | Example | Notes |
| --- | --- | --- |
| `request_id` | `ambar-api/Kf3n2m0001` | Generated by chi; returned to the client as `X-Request-Id` and inside error bodies |
| `http.request.method` | `POST` | |
| `http.route` | `/v1/auth/email/verify` | The route pattern, never the raw path or query, so IDs and tokens stay out of the logs |
| `http.response.status_code` | `200` | |
| `duration_ms` | `12` | Server time in milliseconds |
| `client.address` | `203.0.113.7` | From `X-Real-IP` only when `TRUST_PROXY=true` |

## Domain events

Handlers log significant events with `event` as a stable, dot-separated name. Grep for `event=` or filter on the attribute.

| `event` | Level | Attributes |
| --- | --- | --- |
| `auth.code_requested` | INFO | |
| `auth.signed_in` | INFO | `user_id`, `created` (a new account), `method` (`code`, `link`, `google` or `github`) |
| `auth.oauth_failed` | WARN, ERROR | `provider`, `reason` (the `error` the browser got), `err` (the provider's error code only, never its text). ERROR for `oauth-failed` |
| `auth.signed_out` | INFO | |
| `auth.email_failed` | ERROR | `err` (sign-in email not sent) |
| `auth.failed` | ERROR | `err` (unexpected error, answered with `internal`) |
| `auth.cleanup` | INFO | `challenges`, `sessions` (expired rows deleted) |

## Never logged

Emails, codes, tokens (including providers' access tokens and authorization codes), session IDs, request bodies, raw paths and query strings. If you need to correlate, use `request_id`.

## Correlating a user report

1. Ask for the `requestId` from the error (the UI shows it on unexpected errors) or the time and action.
2. Search the logs for `request_id=<value>`; the request line and any domain events share it.

## Later

When there is real traffic, tracing arrives as middleware: `otelhttp` around the router and `otelslog` as the slog handler, which adds `trace_id` and `span_id` to every line without touching the log calls. Not before.
